# A.D.A V2 & ContextKeep Integration Analysis

## 1. Executive Summary

This document explores the potential benefits, architectural considerations, and implementation strategies for integrating **ContextKeep** (an MCP-compliant infinite long-term memory server) with **A.D.A V2** (Advanced Design Assistant).

Integrating ContextKeep directly aligns with ADA's roadmap, specifically accelerating the development of the **Project Recall** and **Temporal Echoes** features outlined in the `TODO.md`, while offloading complex vector database management, explicit memory indexing, and UI management to a dedicated service.

## 2. Current ADA V2 Memory Architecture vs. ContextKeep

### ADA V2 (Current State)
Currently, ADA V2 handles memory natively using two main components:
*   **`ProjectManager`**: Manages isolated project folders containing a `config.json` and a `chat_history.jsonl` file. It relies heavily on file-based context loading (reading all text files up to 10kb) and localized keyword searches (`search_chat_history`, `search_files`).
*   **`MemoryManager`**: A basic implementation for "architectural memories" (`memory.jsonl`), storing content and tags alongside a `text-embedding-004` vector generated by the Google Gemini SDK. Retrieval is done via basic cosine similarity in Python over the `.jsonl` file or fallback token overlap matching.

### ContextKeep (Capabilities)
ContextKeep is a standalone MCP server backed by SQLite with robust features:
*   **Persistent & Unlimited**: Designed to store unlimited project details, preferences, and decisions.
*   **MCP Protocol**: Exposes 5 strict tools (`list_all_memories`, `retrieve_memory`, `store_memory`, `search_memories`, `list_recent_memories`).
*   **Deterministic Retrieval**: Introduces a reliable two-step retrieval system (`list_all_memories` -> `retrieve_memory`) that prevents LLM hallucinations compared to fuzzy searching alone.
*   **Visual Dashboard**: Includes a fully-featured Web UI (Obsidian Lab V1.2 theme) to manually curate, view, and tag memories.

## 3. Benefits of Integration

Integrating ContextKeep would yield several high-impact benefits for ADA V2:

1.  **Accelerated Delivery of 'Project Recall' & 'Temporal Echoes'**:
    *   **Project Recall** envisions a local, searchable database of user context. ContextKeep already provides the backend (SQLite) and semantic search logic required for this.
    *   **Temporal Echoes** aims to surface past architectural decisions. ContextKeep's `list_all_memories` and semantic search capabilities are purpose-built for this exact workflow.
2.  **Replacing Fragile `.jsonl` with SQLite**:
    *   ADA's `MemoryManager` currently appends to a `memory.jsonl` file and calculates cosine similarity in Python memory for every search. As memory grows, this will become slow and memory-intensive. ContextKeep uses a robust SQLite database, ensuring performance at scale.
3.  **Cost and Token Savings**:
    *   ADA currently attempts to read *all* text files in a project (`get_project_context`) into the prompt. ContextKeep encourages a "pull" model where the AI queries the directory index (`list_all_memories`) and only retrieves specific, highly relevant memories, drastically reducing token usage and Gemini API costs.
4.  **Stand-Alone UI for Memory Curation**:
    *   Users get a dedicated interface (ContextKeep's Web UI) to manage their assistant's brain out-of-the-box, saving the effort of building complex memory-management screens natively within the ADA V2 Electron frontend.
5.  **Deterministic Accuracy**:
    *   The `list_all_memories` index prevents the agent from "guessing" memory keys, ensuring it reliably pulls the exact architectural constraint or preference needed.

## 4. Architectural Integration Options

ContextKeep is designed as an MCP server. ADA V2 must implement an MCP Client to communicate with it. There are two primary deployment models to consider:

### Option A: ADA V2 as a "Bring Your Own Server" Client (Remote/SSE)
In this model, the user runs the ContextKeep server independently (e.g., as a systemd service on a homelab or a background process) and ADA connects to it via HTTP/SSE.

*   **Pros**:
    *   True separation of concerns. ADA remains lightweight.
    *   A single ContextKeep instance could serve ADA *and* the user's IDE (Cursor/Windsurf) simultaneously, creating a truly unified "brain" across all tools.
    *   Easier implementation in ADA (just an HTTP SSE client).
*   **Cons**:
    *   Requires the user to install, configure, and manage two separate applications.
    *   Breaks the "one-click install" experience of ADA V2.

### Option B: ADA V2 Manages the ContextKeep Process (Local/Stdio)
In this model, ContextKeep is bundled as a dependency (or a git submodule) of ADA V2. ADA's Python backend spawns the ContextKeep server as a subprocess communicating over standard I/O (Stdio).

*   **Pros**:
    *   Seamless user experience. The memory server starts and stops with ADA automatically.
    *   Zero configuration required by the end-user.
*   **Cons**:
    *   ADA takes on the burden of managing another Python environment/process lifecycle.
    *   Memories are siloed to ADA (unless ADA exposes the ContextKeep port to other apps).
    *   Requires implementing an MCP Stdio client in ADA's `backend/`.

### Recommended Approach
**Option A (with automatic fallback)** is the most flexible. ADA V2 could accept an `MCP_CONTEXTKEEP_URL` in its `.env` file for remote homelab setups (SSE). If not provided, ADA could optionally attempt to spawn a local ContextKeep subprocess via Stdio if the repository is detected alongside it.

## 5. Implementation Roadmap for ADA V2

If we decide to proceed, the implementation would involve:

1.  **Add MCP Client Support**: Use the official `mcp` Python SDK (or `httpx`/`websockets`) within `backend/` to act as an MCP client.
2.  **Tool Registration**: Map ContextKeep's 5 MCP tools dynamically into ADA's Gemini tool registry (`backend/tools.py`).
3.  **Prompt Engineering**: Update ADA's `DEFAULT_SYSTEM_PROMPT` in `ProjectManager` (or the upcoming 'Temporal Echoes' feature) to instruct the AI on the *Memory Index Protocol*: "Always call `list_all_memories` first before retrieving."
4.  **Deprecate `MemoryManager`**: Once ContextKeep is connected, phase out `backend/memory_manager.py` and the `memory.jsonl` files to avoid maintaining duplicate memory systems.
5.  **Context Injection**: Refactor `ProjectManager.get_project_context()` to rely more on the MCP memory search rather than dumping all local files into the prompt blindly.

## 6. Conclusion

Integrating ContextKeep is highly recommended. It immediately fulfills major portions of the JARVIS-level vision outlined in ADA's `TODO.md` while migrating the fragile `.jsonl` embedding logic to a battle-tested SQLite MCP implementation. It enhances ADA's capabilities from a localized file-reader to an entity with true, persistent, cross-session memory.
